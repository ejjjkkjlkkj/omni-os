**Un ordinateur accessible dès l'allumage.** Première version complète de la chaîne
avant système d'omni-os : réglages du BIOS lus à voix haute, chargeur UEFI parlé, noyau
x86-64 qui parle lui aussi, récupération Windows accessible et voix ST pour WinPE/WinRE.

Tous les binaires ci-dessous ont été construits à partir du commit tagué, **seulement après
le succès de toute la CI**, **uniquement avec des outils libres** (rustc/LLVM, clang/lld,
GCC mingw-w64, sous Linux), **deux fois sur des machines indépendantes avec un résultat
identique à l'octet près**, puis **démarrés dans QEMU avant publication**.

## Contenu

| Fichier | Rôle |
|---|---|
| `omni-os-uefi-x86_64.img.gz` | image disque GPT prête à démarrer (chargeur + noyau) : `gunzip`, puis écrire sur une clé USB ou démarrer dans QEMU/VMware |
| `BOOTX64.EFI` | chargeur UEFI : lecteur d'écran, menu de démarrage et Setup parlés, état de sécurité, braille, audio HDA/AC'97/virtio/USB/haut-parleur, découverte réseau en lecture seule |
| `KERNEL.BIN` | noyau x86-64 : mémoire virtuelle W^X, ordonnanceur préemptif, ring 3, APIC/IOAPIC, PCIe, NVMe/AHCI/virtio, xHCI/USB HID, ACPI, voix HDA, lecteur d'écran, braille |
| `NAVIGATION.EFI` | navigation parlée des menus du BIOS (HII) |
| `st.exe`, `st_synth.dll`, `libst_synth.dll.a`, `st_synth.h` | voix ST pour Windows / WinPE / WinRE : synthèse FR/EN déterministe, bibliothèque C (compilée avec GCC mingw-w64) |
| `st_sapi.dll` | moteur SAPI5 de la voix ST (Narrateur dans WinPE/WinRE, et tout client SAPI) |
| `st-linux-x86_64`, `libst_synth.so` | voix ST pour Linux |
| `REPRODUCIBLE` | empreintes identiques obtenues par la reconstruction indépendante |
| `boot-proof.log` | journal du démarrage QEMU de l'image publiée (marqueurs `AW_*`) |
| `SHA256SUMS` | empreintes de tous les fichiers |

## Ce qui est prouvé à chaque changement

Démarrage réel dans QEMU avec les voix du chargeur et du noyau réellement jouées ; navigation
du BIOS au clavier avec audio identique au bit près à la référence ; C compilé avec gcc,
clang et MSVC sans avertissement, sanitizers et analyseur statique ; rustfmt et clippy
`-D warnings` ; 278 + 37 tests Python, 39 tests de la voix, harness SAPI5 et test d'ABI ;
intégrité des sources et des 74 archives. Détails : [README](https://github.com/ejjjkkjlkkj/omni-os#qualité).

## Tout est à nous

Tout ce qui parle est produit par omni-os : la voix ST pour les clips du chargeur, du noyau et
de `NAV.BIN`, VoiceCore pour la navigation, le synthétiseur formantique du chargeur pour le
texte dynamique. Aucune voix de Microsoft ni d'un autre éditeur n'est embarquée, et aucun
outil propriétaire n'intervient dans la construction.

## Sécurité

Réseau fermé par défaut dans le chargeur (aucun paquet émis). Positionnement face aux
NIST SP 800-193, 800-147, 800-155, 800-218 et à SLSA :
[SECURITY-FRAMEWORK.md](https://github.com/ejjjkkjlkkj/omni-os/blob/main/docs/SECURITY-FRAMEWORK.md).

## Limites connues (dites clairement)

- **Pas encore de trafic réseau** : DHCP, HTTPS, remédiation signée, IDS réseau et VPN sont
  planifiés ([UEFI-CAPABILITIES.md](https://github.com/ejjjkkjlkkj/omni-os/blob/main/docs/UEFI-CAPABILITIES.md)).
- **Détection d'intégrité partielle** : l'état Secure Boot et TPM est annoncé, mais le journal
  TCG et les PCR ne sont pas encore vérifiés.
- **Recovery Core natif** non construit : la récupération passe par WinRE accessible.
- **USB Audio** : configuration du flux faite, lecture isochrone pas encore aboutie.
- **`SCREENREADER.EFI`** n'est pas publié : son `NAV.BIN` contient les textes du BIOS de chaque
  constructeur et doit être fabriqué par le propriétaire de la machine
  ([notes](https://github.com/ejjjkkjlkkj/omni-os/blob/main/uefi-screenreader/boot/uefi-hii-graph-prompt-speech-v1/RELEASE.md)).
- **Récupération par WinRE** : WinRE est un composant de Microsoft, non libre et non livré
  ici ; le chemin entièrement libre sera le Recovery Core natif.
- **Image disque** : son contenu (chargeur, noyau) est reproductible, mais le conteneur FAT
  porte un identifiant et des dates propres à chaque construction ; elle n'est donc pas dans
  `REPRODUCIBLE`, alors que les binaires qu'elle contient le sont.
- **Voix neuronale** non incluse (dépendances GPL-3.0 optionnelles) : la voix ST compacte est livrée.
- **Matériel réel** : preuves obtenues sur ASUS M1603QA et AMD Ryzen 7 5800H ; les autres
  machines restent à valider.
- **Voix** : la règle d'ouverture de la glotte documentée pour les occlusives voisées n'est pas
  appliquée (comportement conservé, changement à juger à l'écoute).
